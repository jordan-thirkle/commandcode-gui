The Gauntlet Loop

A repeatable, evidence-backed workflow for building games with AI agents — split, build, check, critique real pixels, iterate.

Why builders should never grade their own work

The single biggest failure mode in AI-assisted development is the agent reviewing its own output. The Gauntlet Loop fixes that with a hard rule: a separate agent with fresh context grades the real rendered frame, never a summary.

The rule

Independent critic

Every visual system is judged by a fresh-context critic agent that reads real screenshots — never a builder's description of what it made.

The bar

Blind A/B against AAA

Frames are compared against a real reference (for shooters, a Call of Duty frame). If it loses, the critic names the single biggest gap and sends it back.

The loop

Evidence over vibes

Every round ends with a screenshot, a test result, or a verdict. Progress is visible, recorded, and repeatable.

The five phases

The Gauntlet Studio automates exactly this loop in the GUI. Each phase produces something the next phase can act on.

Define the artifact and the bar

Pick one concrete deliverable — a map's lighting, a weapon viewmodel, a HUD — and name the reference bar it must clear. "Good for AI" is not a bar.

Split into independent systems

Break the work into the smallest independently judgeable pieces. Each system gets isolated file ownership so builders never step on each other.

Fan out builders

Each system runs as its own agent session with a focused prompt and a strict ownership boundary. The Gauntlet Studio runs them in sequence, capturing output per system.

Run automated checks

Immediately after builders return, the studio runs the project's checks (syntax, headless simulation, screenshot capture). A failing check records evidence and skips the critic.

Grade real pixels, then iterate

The critic agent reads the real screenshot and returns PASS or FAIL — and on FAIL, a severity (1–10) and a surgical work order. Fix the single biggest gap and run the next round.

What a critic verdict looks like

The critic is trained to be brutal and precise. Here is the shape of a useful FAIL verdict.

# Critic verdict — round 3, system: Map / lighting
FAIL
severity: 9

The lighting is flat and the ground reads as a single material.
The sun has no warm bias and the contact shadow is barely visible.

WORK ORDER: Raise the sun intensity to 1.8, set ground roughness
to 0.4, and add a warm bounce fill from the left. Done = the frame
clears the reference at reference exposure, no blown highlights.

One gap. One fix. A concrete definition of done. That is what makes the loop converge instead of churning.

Why it works

Fresh context catches blind spots

The critic never saw the builder's session, so it cannot be talked into agreeing. It only sees pixels.

Isolated ownership prevents regressions

Builders own disjoint paths, so one system's fix cannot silently break another's work.

Evidence gates every "done"

A screenshot plus a PASS verdict is a definition of done you can ship. A summary is not.

Gauntlet Loop FAQ

Does the critic grade a description of the work?

No. It reads a real screenshot file from the rendered game — the same way a human art director would. If no real screenshot exists, the critic refuses to judge.

What happens when a check fails?

The round records the evidence and stops before the critic phase. There is no point grading pixels on a broken build — fix the check first.

How many rounds does a system need?

Until the critic passes, or the critic identifies a genuine asset-pipeline ceiling. The loop is bounded by a max-rounds setting so it cannot run forever.

Is this only for 3D shooters?

No. The pattern applies to any visual or mechanical system: UI screens, animation, audio-reactive effects, even non-game software with a visual bar.
